# カレンダー日程メモ（Chrome拡張機能）

Googleカレンダーの週表示・日表示で、**既存の予定チップ**や**空いている時間帯**をクリックするだけで、候補日時が自動的にメモに溜まっていくChrome拡張機能です。最大5件まで溜められ、ワンクリックでコピーしてGmailに貼り付け、お客様との日程調整をそのまま進められます。

- **サーバー不要・依存ゼロ** — ビルドも外部ライブラリも使わず、素のJavaScriptだけで完結
- データは **あなたのブラウザの中だけ** に保存されます（外部送信なし）
- 出力形式は `7月25日(土) 10:00〜11:00` のように、日本人のお客様にそのまま送れる書式に固定

## できること

1. Googleカレンダーを開き、拡張機能のアイコンをクリックするとページ内にメモパネルが開く（パネルが開いている間は「取得モード」になる）
2. 週表示・日表示で、**予定チップ**または**空いているマス目**をクリックすると、その日時がメモに追加される
3. 最大5件まで溜められる（6件目以降は追加されず、案内が出る）
4. パネルの「コピー」ボタンで、溜まった候補日時を改行区切りでまとめてコピー
5. Gmailの本文に貼り付けてそのまま送信

出力例（実際にコピーされるテキスト）:

```
7月25日(土) 10:00〜11:00
7月28日(火) 14:00〜15:00
```

## インストール（初回だけ・1分）

Chromeウェブストアには公開していません。「パッケージ化されていない拡張機能」として読み込みます。

1. Chromeで `chrome://extensions` を開く
2. 右上の **「デベロッパーモード」** をONにする
3. **「パッケージ化されていない拡張機能を読み込む」** をクリック
4. このリポジトリの `gcal-schedule-memo` フォルダを選択する
5. ツールバーの拡張機能アイコン（パズルのピース）から、この拡張機能をピン留めしておくと使いやすい

> Chromeを起動するたびに「デベロッパーモードの拡張機能を無効にしますか」というバナーが出ることがありますが、実害はありません。「無効にする」を選ばなければそのまま使えます。

## 使い方

1. `calendar.google.com` を週表示または日表示で開く
2. 拡張機能アイコンをクリック → 画面の右上あたりにメモパネルが開く（このときカーソルが十字になり、グリッドに薄い青枠が出る＝取得モード中）
3. 候補にしたい**予定**や**空いている時間帯**をクリックしていく → クリックのたびにメモへ追加される
4. 「コピー」ボタンを押す → クリップボードにコピーされる
5. Gmailの本文に貼り付ける

### 取得モードの終了

パネルが開いている間は、カレンダー上のクリックがすべてメモ追加用に横取りされます。普段どおりカレンダーを操作したいときは:

- パネルヘッダの **「取得モード」** ボタンをもう一度押す、または
- **Escキー** を押す

いずれもパネル自体は開いたままで、取得モードだけがOFFになります。パネルを閉じる（×ボタン）と、取得モードも自動的にOFFになります。パネルが非表示の間は、クリックの横取りは一切行われません。

### 一覧の操作

- 各行の **×** で個別に削除できます
- **「全消去」** は誤操作防止のため2回押しが必要です（1回目で「もう一度押すと消去」に変わります）
- 一覧は常に時系列の昇順で表示されます（クリックした順ではありません）
- 同じ日時を2回クリックしても重複追加されません
- パネルのヘッダをドラッグすると好きな位置に移動できます（次回開いたときも位置を記憶します）

## 対応範囲

| 表示 | 予定チップ | 空きマス |
| :--- | :--- | :--- |
| 週表示 / 日表示 | ○ | ○ |
| 月表示 / スケジュール表示 | ○（確度は「推定」表示） | ×（時刻の情報が無いため） |
| 年表示 | × | × |

以下は明示的に対象外です（クリックしてもメモには追加されず、理由が案内されます）:

- 終日の予定
- 複数日にまたがる予定
- 日をまたぐ時間帯（例: 23:00〜翌1:00）
- タスク・リマインダー

## 確度（推定バッジ）について

メモの各行には、必要に応じて「推定」「要確認」のバッジが付きます。これは、日時の読み取りに複数の情報源（Googleの内部データ属性、ラベル文字列、画面上の位置など）を使っており、**主要な情報源から確実に読み取れなかった場合**に表示されます。バッジが付いている行は、コピー前に一度目で確認してください。日時が確実に読み取れない場合は、メモに追加せず「読み取れませんでした」と案内するようにしています（推測で日時を作り出すことはしません）。

## うまく動かないとき（キャリブレーション手順）

この拡張機能は、Googleカレンダーの**非公開のページ構造**（クラス名や内部属性）に一部依存しています。Google側の更新でページ構造が変わると、日時の読み取り精度が落ちることがあります。

その場合は、以下の手順で「調査用スクリプト」を実行し、実際のページ構造を確認してください。

1. `calendar.google.com` を週表示で開く
2. DevToolsを開く（Mac: `Cmd+Option+J` / Windows: `Ctrl+Shift+J`）
3. コンソールに **`allow pasting`** と直接入力してEnter
   （Chromeはコンソールへの貼り付けを既定でブロックしているため、これを入力しないと次の手順で貼り付けができません）
4. `tools/probe.js` の中身を全部コピーしてコンソールに貼り付け、Enter
5. 案内に従って、**時刻付きの既存の予定を1つ**、続けて**空いている時間帯を1つ**クリックする
6. コンソールで次のいずれかを実行し、結果をコピーする
   - `copy(GSM_PROBE.dump())` … クリップボードに直接コピーされる
   - `GSM_PROBE.dump()` … コンソールにJSON文字列が表示される
7. コピーした内容をClaudeに渡す（「日程メモ拡張機能の調査結果」として貼り付ければOK）と、`src/extract.js` のセレクタ・正規表現を実測値に合わせて更新します

調査用スクリプトの出力は、日付・時刻の骨格だけを残し、予定タイトルや参加者名などの単語は自動的に `#` でマスクされます。ただし完全ではないため、**貼り戻す前に必ず中身を目視確認**してください。

## 動作確認チェックリスト（実機での最終確認）

自動テスト（後述）はあくまで模造DOMに対する検証です。Googleの実際のカレンダーに対しては、以下を一度手動で確認してください。

- [ ] 週表示: 既存の予定チップをクリック → 正しい日時がメモに追加され、予定の詳細画面は開かない
- [ ] 週表示: 空いているマス目をクリック → 予定作成画面が開かず、クリックした時刻付近でメモに追加される
- [ ] 空きマスをドラッグしても何も起きない（ドラッグでの予定作成が抑止されている）
- [ ] 終日の予定をクリック → 追加されず「終日の予定は対象外です」と案内される
- [ ] 日表示・月表示・スケジュール表示でも、対応範囲の表どおりに動く
- [ ] Escキーでカレンダーの通常操作（予定作成・詳細表示）に戻れる
- [ ] パネルを閉じた状態では、拡張機能の存在に一切気づかない（普段どおり操作できる）
- [ ] コピーしてGmailの本文に貼り付け、書式が崩れていない
- [ ] ダークテーマ、ブラウザの拡大縮小（80%・150%など）でも表示・時刻の読み取りが崩れない
- [ ] カレンダーの表示タイムゾーンを変えても、画面表示どおりの時刻でメモされる
- [ ] タブを再読み込みしても候補が保持され、別のカレンダータブを開いても同じ内容が見える

## テスト

### 単体テスト（依存ゼロ・即実行可）

`src/*.js` の純粋関数群（書式生成・datekeyの符号化復号・ラベルのパース・幾何計算・状態管理）を検証します。

```bash
node gcal-schedule-memo/test/run.js
```

### E2Eテスト（Playwright・任意）

Googleカレンダーの週表示を模した静的HTML（`test/fixtures/week-view.html`）に対し、実際のChromiumへ拡張機能をロードして「クリック横取り→抽出→パネル表示→コピー」までを一気通貫で検証します。拡張機能のロードにはヘッドフルなブラウザが必要なため、`xvfb-run` で仮想ディスプレイを使います。

```bash
cd gcal-schedule-memo/test/e2e
npm install   # 初回のみ（playwrightを取得）
cd ../../..
xvfb-run -a node gcal-schedule-memo/test/e2e/picker.spec.js
```

これはあくまで「拡張機能側のロジックが、想定した構造に対して正しく動くか」の確認です。**Googleカレンダーの実際のDOMに対して動く保証にはなりません**（fixtureは自作の模造品のため）。実機での確認は上のチェックリストで行ってください。

## 技術メモ

- **依存ゼロ・ビルドなし** — `src/*.js` は素のJavaScript。ブラウザ（コンテンツスクリプトとして）とNode（テストとして）の両方で動くよう、各ファイルの末尾で `module.exports`（Node）と `globalThis.GSM.xxx`（ブラウザ）の両対応にしています。MV3のコンテンツスクリプトは複数ファイルを列挙しても同一のJSレルムで実行されるため、各ファイル全体をIIFEで包み、トップレベルの変数名が他ファイルと衝突しないようにしています。
- **保存先** — `chrome.storage.local` のキー `gcalScheduleMemo.v1` に、`schemaVersion` 付きの1ドキュメントとして保存します（`wardrobe/index.html` と同じ設計）。データは端末内のみで、外部送信は一切ありません。
- **日時の抽出は階層フォールバック方式** — Googleの内部データ属性（`data-datekey` など）を主軸にしつつ、それが取れない場合はラベル文字列や画面上の位置から推定します。情報源によって「確度（high/medium/low）」を付け、確度が低い場合はメモ上にバッジで示します。どの情報源からも日時が確定できない場合は、値を作り出さずに読み取り失敗として案内します。
- **GoogleのDOMは非公開仕様** — クラス名などは将来変わり得る前提で設計しています（上記「うまく動かないとき」参照）。壊れても、調査用スクリプトで実測 → 抽出ロジックを更新、という手順で直せるようにしてあります。
- **権限は最小限** — `manifest.json` の権限は `storage` と `https://calendar.google.com/*` のみです。クリップボードへのコピーはユーザー操作起因の `navigator.clipboard` API（失敗時は `execCommand('copy')` にフォールバック）で行うため、追加の権限は不要です。
