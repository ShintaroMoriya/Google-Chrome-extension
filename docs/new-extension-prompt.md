# 新しい拡張機能を作るためのプロンプト

`gcal-schedule-memo`（カレンダー日程メモ）で確立したUI/UXを**型**として固定し、同じ体験の拡張機能を別の用途向けに作るためのプロンプトです。

## 使い方

1. 下の **「穴埋め欄」** を自分の作りたい機能に合わせて書き換える
2. `--- ここから下をすべてコピー ---` 以降を全部コピーして Claude に貼り付ける
3. 出てきたコードを `Google-Chrome-extension/<拡張機能名>/` に配置し、`chrome://extensions` から読み込む

穴埋め欄だけ埋めれば、設計方針・コード規約・受け入れ基準はプロンプト側が全部持っているので、毎回ゼロから設計を説明し直す必要はありません。

### 穴埋め欄の記入例

| 欄 | 記入例（Gmail向けの場合） |
| :--- | :--- |
| 拡張機能名 | メール定型文ピッカー |
| ディレクトリ名 | `gmail-snippet-picker` |
| 対象サイト | `https://mail.google.com/*` |
| 解決したい困りごと | 定型文をNotionから毎回コピペしていて、送信のたびにタブを往復している |
| 収集/操作の対象 | 登録済みの定型文（本文テンプレート） |
| 「クリックで溜める」対象 | 定型文リストの行 |
| 最終的な出力 | 選んだ定型文を、宛名を差し込んだ状態でクリップボードにコピー |
| 上限 | 1件（選択式なので溜めない） |

## 1. これは「ゼロから設計する」依頼ではありません

UI/UX・アーキテクチャ・コード規約は下記で**すでに確定済み**です。あなたの仕事は、確定した型に穴埋め欄の内容を流し込むことです。型から外れた設計（ブラウザアクションのポップアップUI、Reactやビルドツールの導入、外部APIへの送信など）は採用しないでください。型を変えるべき理由が本当にあると判断した場合は、実装を始める前にその理由を述べて確認を取ってください。

## 2. Design System（15項目・すべて必須）

### UIの形

1. **UIはページ内フローティングパネル**にする。ブラウザアクションのポップアップ（`action.default_popup`）は**使わない**。理由: ポップアップはページをクリックした瞬間に閉じるため、「パネルを開いたままページをポチポチ押して溜める」という中核体験が成立しない。`default_popup` を持たせないことで `chrome.action.onClicked` が発火する。
2. **パネルは Shadow DOM（`mode: 'open'`）で隔離**する。ホスト要素は `all: initial` でリセットし、`:host { all: initial; }` から始まるCSSを Shadow 内に閉じる。対象サイト側のCSSと相互に干渉させない。`z-index` は `2147483000`。
3. **アイコンクリック = パネルの表示/非表示トグル**。`background.js` はサービスワーカーとして「トグルして」というメッセージをタブに送るだけの薄い層にする。対象サイト以外のタブでアイコンが押されたら、対象サイトを新規タブで開く（ユーザーを迷わせない）。コンテンツスクリプト未注入で `sendMessage` が失敗したら、タブをリロードして注入をやり直す。
4. **パネルはヘッダのドラッグで移動でき、位置を記憶する**。座標は常にビューポート内にクランプする（`clampToViewport`）。ダークモードは `@media (prefers-color-scheme: dark)` で必ず対応する。

### 「モード」の扱い（最重要）

5. **「取得モード」を明示的な状態として持つ**。パネルを開くと自動でON、閉じると必ずOFF。ヘッダのトグルボタンと **Escキー** でモードだけをOFFにできる（パネルは開いたまま）。
6. **モードがOFFの間は、ページのイベントに一切干渉しない**。「知らないうちにクリックが横取りされている」状態を絶対に作らない。モード中は視覚的アフォーダンス（`cursor: crosshair`、対象領域のアウトライン）を必ず出し、モード中であることが一目で分かるようにする。
7. **イベント横取りの安全則**（守らないと壊れます）:
   - `pointerdown` に **`preventDefault()` を絶対に呼ばない**。Pointer Events仕様上、pointerdownの既定動作を止めると互換マウスイベント（mousedown/click）が発火しなくなり、自分自身の抽出処理（clickで実行）が動かなくなる。pointerdownでは `stopImmediatePropagation()` のみ。
   - 横取りは **captureフェーズ**で行う（サイト側のハンドラはバブルフェーズで待つため、captureで先回りできる）。
   - **データの確定は `click` でのみ**行う（ドラッグと区別するため）。
   - **自分のパネル（Shadow DOMホスト）内のイベントは素通し**する（`composedPath()` にホストが含まれるかで判定）。
   - `[role="dialog"]` / `[role="navigation"]` の中では横取りしない。

### 「何が起きるか」を先に見せる

8. **ホバー時に「クリックしたら何が起きるか」を枠＋ラベルでプレビュー**する。`pointermove` は `requestAnimationFrame` でスロットルする（キャッシュはせず毎回DOMから再計算し、スクロール・リサイズ・ビュー切替を気にしなくてよい設計にする）。
9. **プレビューと確定は同一の計算関数を呼ぶ（WYSIWYG を構造で保証）**。「表示用のロジック」と「確定用のロジック」を2つ持つことを禁止する。プレビュー用オーバーレイはパネルとは別の Shadow DOM ホストにし、**`pointer-events: none` をホストと内部要素の両方に指定**してクリックを一切妨げない。プレビュー側は描画専用で、抽出ロジックを一切持たない。
10. **確度を `high` / `medium` / `low` の3段階で持つ**。プレビュー枠の色を確度に連動させ（青=確実 / 黄=推定 / 赤=要確認）、一覧では **`low` の行にだけ「要確認」バッジ**を出す。**どの情報源からも値が確定できない場合は、値を捏造せずエラーとして案内する**（推測で作り出さない）。

### 操作のフィードバック

11. **破壊的操作は2度押し**にする。1回目でボタンが赤くなり「もう一度押すと消去」に変わり、3秒で自動的に解除される。
12. **すべての操作に即時フィードバックを返す**: 追加時は該当行を一瞬光らせる（`flash` アニメーション）、コピー成功時はボタン文言を「コピーしました ✓」に1.2秒だけ変える、失敗・重複・上限到達はトースト（`role="status"` / `aria-live="polite"`）で理由を伝える。**何も起きなかったように見える経路を残さない**。
13. **上限を設け、残数を常に表示する**（例: `3 / 5 件`）。同じものを2回拾っても重複追加しない。一覧は追加順ではなく**意味のある順序（時系列など）で常にソート**して表示する。

### 状態とコード

14. **永続化は `chrome.storage.local` に `schemaVersion` 付きの1ドキュメント**として行う。読み込み時は必ず `migrate()` を通し、**未知のバージョン・壊れたデータは安全側に倒して初期状態にフォールバック**する（部分的に壊れた状態で使わせない）。保存はデバウンスする（連続操作で毎回書き込まない）。
15. **状態更新ロジックは純粋関数（リデューサ）に分離**し、ストレージ層と切り離す。`addEntry` は `{ state, result: 'added' | 'duplicate' | 'full' }` のように**結果の種別を返す**（呼び出し側がフィードバックを出し分けられるように）。ストレージバックエンドは `chrome.storage` が無い環境では**メモリ実装に自動フォールバック**させ、Node と Playwright フィクスチャの両方でUIを動かせるようにする。

## 3. コード規約（そのまま踏襲すること）

- **依存ゼロ・ビルドなし**。素のJavaScriptのみ。npm パッケージ・バンドラ・TypeScript・フレームワークを導入しない（テスト用の Playwright だけは例外で、`test/e2e/` に隔離する）。
- **各ソースファイルは全体を IIFE で包む**。MV3 のコンテンツスクリプトは複数ファイルを列挙しても同一のJSレルムで実行されるため、包まないとトップレベルの `const` / `function` が他ファイルと衝突する。
- **各ファイルの末尾でブラウザ/Node の両対応エクスポート**をする:

  ```js
  const api = { /* ... */ };
  if (typeof module !== 'undefined' && module.exports) {
    module.exports = api;
  } else {
    globalThis.XXX = globalThis.XXX || {};
    globalThis.XXX.format = api;
  }
  ```

  （`XXX` は拡張機能ごとの短い名前空間。`gcal-schedule-memo` は `GSM`）
- **DOMを触る関数は、require された時点では何もしない**。`createPanel()` / `createPreview()` を呼ぶまで `document` に触れないこと（Node でのテスト時に require 自体が安全であるため）。
- **出力書式の正本は1ファイルだけ**に置く（`src/format.js`）。他のどのファイルからも出力文字列を直接組み立てない。
- **日時は「壁時計フィールド」（y, m, d, sh, sm, eh, em）で保持**し、epoch 経由の変換やタイムゾーン変換を行わない（画面表示どおりの時刻を保つため）。日付を扱う機能でなくても、「画面に見えている値をそのまま保持する」という原則は同じ。
- **すべてのファイル冒頭に、日本語のブロックコメントで「目的」と「設計上の制約」を書く**。特に「なぜこうしなかったか」（例: なぜポップアップを使わないか、なぜ pointerdown で preventDefault しないか）を残す。UI文言・コメント・README はすべて日本語。
- **権限は最小限**。`permissions` は本当に必要なものだけ、`host_permissions` は対象サイトのみ。クリップボードはユーザー操作起因の `navigator.clipboard.writeText()` を使い、失敗時のみ `textarea` + `execCommand('copy')` にフォールバックする（クリップボード権限は要求しない）。
- **SPA対策**: パネルのホスト要素がDOMから外れたら再アタッチする（`MutationObserver` + 3秒間隔の保険）。

## 4. 成果物

`<ディレクトリ名>/` の中だけで完結させ、他の拡張機能とファイル・依存を共有しないこと。

```
<ディレクトリ名>/
  manifest.json          # MV3。default_popup を持たない
  background.js          # アイコンクリック→トグルメッセージ送信のみ
  src/
    format.js            # 出力書式の正本（純粋関数のみ）
    extract.js           # ページから値を拾う（プレビューと確定で共有する唯一の計算経路）
    store.js             # schemaVersion / 純粋リデューサ / ストレージ抽象
    panel.js             # Shadow DOM パネル（描画とコールバック配線のみ。状態を書き換えない）
    preview.js           # pointer-events:none のプレビューオーバーレイ（描画専用）
    content.js           # エントリポイント。イベント横取りと各層の結線
  test/
    run.js               # 依存ゼロの簡易テストランナー
    *.test.js            # module.exports = [{ name, fn }, ...] を返す
  icons/                 # 16 / 48 / 128
  README.md
```

- 純粋関数（書式・状態遷移・パース・幾何計算）には**必ず単体テストを書く**。`node <ディレクトリ名>/test/run.js` だけで実行でき、外部依存を必要としないこと。テストファイルは `module.exports = [{ name, fn }, ...]` の配列を返す形式にし、`node:assert` だけを使う。
- `README.md` には次を必ず含める: できること / インストール手順（パッケージ化されていない拡張機能として読み込む手順）/ 使い方 / 対応範囲と対象外の表 / **実機での動作確認チェックリスト**（自動テストは模造DOMに対する検証にすぎないことを明記）/ テストの実行方法 / 技術メモ。
- 対象サイトの**非公開のDOM構造**（クラス名や内部データ属性）に依存する場合は、`tools/probe.js`（DevToolsのコンソールに貼り付けて実際の構造を実測し、個人情報をマスクしてダンプする調査用スクリプト）も作り、README に「うまく動かないときのキャリブレーション手順」として書くこと。

## 5. 受け入れ基準（実装後、自分でこの順に確認する）

- [ ] パネルを閉じている間は、拡張機能の存在に一切気づかない（対象サイトが普段どおり操作できる）
- [ ] 取得モードON/OFFが、カーソル形状とアウトラインで一目で分かる
- [ ] Escキーでモードだけが解除され、パネルは開いたままになる
- [ ] ホバー時のプレビュー内容と、クリックして実際に追加される内容が完全に一致する
- [ ] 値が確定できないケースで、捏造せず理由がトーストで案内される
- [ ] 重複追加・上限到達が、それぞれ専用の文言で案内される
- [ ] 全消去が2度押しでのみ実行される（3秒放置で解除される）
- [ ] コピーが成功し、貼り付け先で書式が崩れない
- [ ] ダークテーマ、ブラウザ拡大縮小（80% / 150%）で表示が崩れない
- [ ] タブを再読み込みしても内容が保持され、別タブでも同じ内容が見える
- [ ] `node <ディレクトリ名>/test/run.js` が全件成功する
- [ ] `manifest.json` の権限が、実際に使っているものだけになっている
